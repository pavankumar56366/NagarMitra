# Copy NagarMitra into this project

Your uploaded project is a complete civic-complaints app (NagarMitra) built on the same stack this project uses, so it can be brought over as-is rather than rebuilt.

## What the app contains

- **Citizen side**: report a problem with a photo, see your reports, waste-segregation guidance, profile.
- **Staff/worker side**: dashboard, assigned reports, duty toggle, profile.
- **Admin side** (sign-in protected): overview, complaints list and detail, map, zones, workers, escalations, reports, settings.
- **Sign-in** for citizens, workers and staff, with separate roles and permissions.
- **Photos and avatars** kept private, shown through short-lived links.
- **AI photo check** used when a complaint is submitted.
- 13 data tables with role-based access rules, plus a landing page.

## Steps

1. Copy all app code, pages, components, styles, icons and the web app manifest into this project (no `.git` data, no secret files).
2. Install the extra packages the app needs (map, camera, AI, charts, forms).
3. Turn on Lovable Cloud so the database, sign-in, file storage and server code work here.
4. Recreate the full database: all 13 tables, roles, access rules, helper functions, the two private photo/avatar buckets and their rules, and the reference rows the app ships with (zones, waste categories).
5. Verify: the app builds, the landing page and each main screen load, sign-in works, and one complaint can be created and read back.
6. Clean up any test rows created during verification.

## Technical details

- Stack matches exactly: TanStack Start v1 + React 19 + Tailwind v4 + Supabase-backed Lovable Cloud, so no framework migration is needed; TanStack package versions stay at this template's pinned versions.
- Server logic stays in `createServerFn` modules (`vision.functions.ts`, `citizen-verification.functions.ts`, `worker-accounts.functions.ts`) with the existing auth middleware; the AI call keeps using the Lovable AI Gateway.
- The 16 uploaded migration files are consolidated into a single ordered migration for this project, including `GRANT`s for every public table, `has_role`/`is_staff` security-definer functions, RLS policies, `storage.buckets` creation for `complaint-photos` and `avatars`, storage object policies, and literal `INSERT`s for seed reference rows.
- `src/integrations/supabase/*` files are regenerated by the Cloud integration rather than copied verbatim where they conflict.
